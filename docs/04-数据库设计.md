## 一、数据库概述

### 1.1 技术选型

- **数据库**：Supabase（基于 PostgreSQL）
- **ORM/客户端**：`@supabase/supabase-js` + 自动生成的 TypeScript 类型
- **安全**：Row Level Security（RLS），所有表默认启用
- **文件存储**：Supabase Storage（图片 / 附件）

### 1.2 ER 关系总览

**关系说明：**
- `profiles` 与 Supabase Auth 用户 1:1 关联
- 其他业务表均为独立实体，通过 `status` 字段控制公开/草稿
- 无复杂多对多关联表，标签使用 PostgreSQL 数组类型 `text[]`

| `name` | `text` | NOT NULL | 姓名 |
| `title` | `text` | — | 职位头衔（如 "Frontend Developer"） |

| `email` | `text` | — | 公开联系邮箱 |
| `github_url` | `text` | — | GitHub 主页 URL |
| `linkedin_url` | `text` | — | LinkedIn URL |
| `twitter_url` | `text` | — | Twitter/X URL |
| `website_url` | `text` | — | 个人网站 URL |
| `created_at` | `timestamptz` | NOT NULL DEFAULT now() | 创建时间 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT now() | 更新时间 |

- `user_id` 唯一索引

## 三、Row Level Security（RLS）策略

### 3.1 通用原则

- 所有表**默认启用 RLS**
- 公开数据：`status = 'published'` 的记录所有人可读
- 写操作：仅 `authenticated` 用户可执行（即 Admin）
- `profiles` 表：仅 owner 可写，所有人可读

### 3.2 各表 RLS 策略

#### projects 表

```sql
-- 已发布项目公开可读
CREATE POLICY "Published projects are viewable by everyone"
  ON projects FOR SELECT
  USING (status = 'published');

-- Admin 可查看所有项目（包括草稿）
CREATE POLICY "Admins can view all projects"
  ON projects FOR SELECT
  USING (auth.role() = 'authenticated');

-- Admin 可创建项目
CREATE POLICY "Admins can create projects"
  ON projects FOR INSERT
  WITH CHECK (auth.role() = 'authenticated');

-- Admin 可更新项目
CREATE POLICY "Admins can update projects"
  ON projects FOR UPDATE
  USING (auth.role() = 'authenticated');

-- Admin 可删除项目
CREATE POLICY "Admins can delete projects"
  ON projects FOR DELETE
  USING (auth.role() = 'authenticated');
```

#### articles 表

```sql
-- 已发布文章公开可读
CREATE POLICY "Published articles are viewable by everyone"
  ON articles FOR SELECT
  USING (status = 'published');

-- Admin 可查看所有文章
CREATE POLICY "Admins can view all articles"
  ON articles FOR SELECT
  USING (auth.role() = 'authenticated');

-- Admin 可写文章
CREATE POLICY "Admins can modify articles"
  ON articles FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
```

#### profiles / experiences / skills 表

```sql
-- 所有人可读（简历是公开的）
CREATE POLICY "Profiles are viewable by everyone"
  ON profiles FOR SELECT
  USING (true);

CREATE POLICY "Experiences are viewable by everyone"
  ON experiences FOR SELECT
  USING (true);

CREATE POLICY "Skills are viewable by everyone"
  ON skills FOR SELECT
  USING (true);

-- 仅 Admin 可写
CREATE POLICY "Admins can modify profiles"
  ON profiles FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');

CREATE POLICY "Admins can modify experiences"
  ON experiences FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');

CREATE POLICY "Admins can modify skills"
  ON skills FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
```

#### experiments 表

```sql
-- 已发布实验模块公开可读
CREATE POLICY "Published experiments are viewable by everyone"
  ON experiments FOR SELECT
  USING (status = 'published');

-- Admin 可写
CREATE POLICY "Admins can modify experiments"
  ON experiments FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
```

#### site_settings 表

```sql
-- 所有人可读
CREATE POLICY "Site settings are viewable by everyone"
  ON site_settings FOR SELECT
  USING (true);

-- 仅 Admin 可修改
CREATE POLICY "Admins can modify site settings"
  ON site_settings FOR UPDATE
  USING (auth.role() = 'authenticated');
```

## 四、Storage 存储桶设计

### 4.1 存储桶清单

| 桶名 | 用途 | 公开访问 | 文件类型 | 大小限制 |
|------|------|---------|---------|---------|
| `project-covers` | 项目封面图 | 公开读 | image/* | 5MB |
| `article-covers` | 文章封面图 | 公开读 | image/* | 5MB |
| `avatars` | 用户头像 | 公开读 | image/* | 2MB |
| `site-assets` | 站点静态资源（Logo 等） | 公开读 | image/* | 2MB |

### 4.2 Storage RLS 策略

```sql
-- 项目封面：公开读，Admin 写
CREATE POLICY "Project covers are public"
  ON storage.objects FOR SELECT
  USING (bucket_id = 'project-covers');

CREATE POLICY "Admins can upload project covers"
  ON storage.objects FOR INSERT
  WITH CHECK (
    bucket_id = 'project-covers'
    AND auth.role() = 'authenticated'
  );
```

## 六、数据库类型生成

### 6.1 自动生成 TypeScript 类型

使用 Supabase CLI 从数据库 schema 自动生成类型：

```bash
# 生成数据库类型到 src/types/database.ts
npx supabase gen types typescript --project-id <your-project-id> > src/types/database.ts
```

### 6.2 类型使用示例

```typescript
import type { Database } from '@/types/database'

type ProjectRow = Database['public']['Tables']['projects']['Row']
type ProjectInsert = Database['public']['Tables']['projects']['Insert']
type ProjectUpdate = Database['public']['Tables']['projects']['Update']
```

## 七、迁移与版本管理

### 7.1 迁移文件目录

```
supabase/
├── migrations/
│   ├── 00000000000000_init.sql          # 初始建表
│   ├── 00000000000001_add_rls.sql        # RLS 策略
│   ├── 00000000000002_add_triggers.sql   # 自动更新 updated_at 触发器
│   └── ...
└── seed.sql                                # 初始化数据
```

### 7.2 updated_at 自动更新触发器

```sql
-- 通用函数：自动更新 updated_at
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 各表添加触发器
CREATE TRIGGER update_projects_updated_at
  BEFORE UPDATE ON projects
  FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER update_articles_updated_at
  BEFORE UPDATE ON articles
  FOR EACH ROW EXECUTE FUNCTION update_updated_at();

-- ... 其他表同理
```

### 7.3 本地开发工作流

```bash
# 启动本地 Supabase
npx supabase start

# 执行迁移
npx supabase db reset

# 推送迁移到远程
npx supabase db push

# 从远程拉取类型
npx supabase gen types typescript > src/types/database.ts
```
