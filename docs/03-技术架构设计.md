## 一、技术栈总览

### 1.1 核心技术栈

| 分类 | 技术选型 | 版本基准 | 选型理由 |
|------|---------|---------|---------|
| **核心框架** | Vue 3 | 3.5+ | Composition API 为核心，TypeScript 一等支持 |
| **开发语言** | TypeScript | 6.0+ | 2026 年 3 月正式发布，类型系统更强大 |
| **构建工具** | Vite | 8.x | 2026 年 3 月发布，生态成熟，HMR 极速 |
| **路由** | Vue Router | 4.x | 官方路由，类型安全，支持导航守卫 |
| **客户端状态** | Pinia | 2.x | Vue 官方推荐，轻量，TypeScript 友好 |
| **Composition 工具** | VueUse | 12.x | 50+ 实用 composable，减少重复代码 |
| **CSS 框架** | Tailwind CSS | 4.x | 原子化 CSS，设计系统基础 |
| **组件库** | shadcn-vue | 2.x | 源码可控、可定制，非黑盒组件库 |
| **服务端状态** | TanStack Query | 5.x (@tanstack/vue-query) | 缓存 / 重试 / 失效 / 后台更新 |
| **数据校验** | Zod | 4.x | TypeScript 优先的 schema 校验 |
| **BaaS 后端** | Supabase | — | Auth + PostgreSQL + Storage + RLS |
| **单元测试** | Vitest | 3.x | Vite 原生测试框架，极速 |
| **E2E 测试** | Playwright | 1.x | 跨浏览器，自动等待，调试友好 |
| **代码规范** | ESLint | 10.x (flat config) | 2026 年已全面 flat config |
| **代码格式化** | Prettier | 3.x | 统一代码风格 |
| **类型检查** | vue-tsc | 2.x | Vue SFC 类型检查 |
| **CI/CD** | GitHub Actions | — | 与 GitHub 仓库原生集成 |
| **部署** | Vercel / Cloudflare Pages | — | 静态托管 + 自动部署 |
| **Node 基线** | Node.js | 24 LTS | 2026 年 9 月当前 LTS 版本 |

### 1.2 技术栈决策原则

> **每一个技术都有对应的业务使用场景，不为了技术而加技术。**

- 不引入：GraphQL / WebSocket / Three.js / 微前端 / AI Agent —— 这些对当前目标会稀释核心价值
- 不选择：Element Plus / Ant Design Vue —— 项目目标是展示自定义 UI 工程能力，而非使用现成组件库

### 2.2 分层职责

| 层级 | 职责 | 可直接引用的下层 |
|------|------|----------------|
| **Views** | 页面组合、路由出口、布局 | Features / Components |
| **Features** | 业务模块自包含：组件 + 逻辑 + 服务调用 | Services / Composables / UI |
| **Services** | API 调用封装、数据转换、错误处理 | Supabase Client / Zod |
| **Stores** | 客户端共享 UI 状态（非服务端数据） | — |
| **Composables** | 跨 feature 复用的业务逻辑 | Services |
| **UI Components** | 纯展示组件（shadcn-vue + 自定义） | 无业务依赖 |

### 3.2 目录设计原则

1. **Feature-first**：业务代码按功能模块组织，而非按文件类型
2. **自包含**：每个 feature 内部包含自己的组件、逻辑、类型、服务
3. **单向依赖**：Features → Services → Supabase，禁止反向依赖
4. **UI 纯净**：`components/ui/` 不含任何业务逻辑，纯展示
5. **共享下沉**：跨多个 feature 复用的才提到全局，避免过度抽象

## 四、状态管理设计

### 4.1 状态分类与边界

```
┌─────────────────────────────────────────────────┐
│                 应用状态                          │
├───────────────────┬─────────────────────────────┤
│   客户端状态      │        服务端状态             │
│   (Client State)  │       (Server State)         │
│   存于客户端内存   │   来自后端 / 需同步           │
├───────────────────┼─────────────────────────────┤
│   → Pinia        │   → TanStack Query          │
│   → 本地 ref      │   → Supabase                │
│                   │                             │
│   例子：          │   例子：                     │
│   · 暗色模式      │   · 项目列表 / 详情          │
│   · 侧边栏折叠    │   · 文章列表 / 详情          │
│   · 命令面板开关  │   · 简历数据                 │
│   · 表单临时状态  │   · Admin 所有 CRUD 数据     │
│   · 组件 UI 状态  │   · 用户登录 session         │
└───────────────────┴─────────────────────────────┘
```

### 4.2 Pinia Stores 设计

**仅存真正需要跨组件共享的客户端 UI 状态：**

| Store | State | Actions | 使用场景 |
|-------|-------|---------|---------|
| `useThemeStore` | `mode: 'light' \| 'dark' \| 'system'` | `toggle()` / `setMode()` | 全站暗色模式切换 |
| `useCommandPaletteStore` | `isOpen: boolean` | `open()` / `close()` / `toggle()` | 全局 ⌘K 命令面板 |
| `useSidebarStore` | `isCollapsed: boolean` | `toggle()` | Admin 侧边栏折叠 |

**禁止**：把从 API 获取的数据存到 Pinia。服务端数据一律走 TanStack Query。

### 4.3 TanStack Query 设计

**Query Keys 约定：**

```typescript
// services/api/queryKeys.ts
export const queryKeys = {
  projects: {
    all: ['projects'] as const,
    lists: () => [...queryKeys.projects.all, 'list'] as const,
    list: (filters: ProjectFilters) => [...queryKeys.projects.lists(), filters] as const,
    details: () => [...queryKeys.projects.all, 'detail'] as const,
    detail: (slug: string) => [...queryKeys.projects.details(), slug] as const,
  },
  articles: {
    all: ['articles'] as const,
    lists: () => [...queryKeys.articles.all, 'list'] as const,
    list: (filters: ArticleFilters) => [...queryKeys.articles.lists(), filters] as const,
    detail: (slug: string) => [...queryKeys.articles.all, 'detail', slug] as const,
  },
  // ... 其他实体
}
```

**Mutation 失效模式：**

```typescript
// 创建/更新/删除后自动刷新列表
const queryClient = useQueryClient()

// 示例：更新项目后
await updateProject(projectId, data)
queryClient.invalidateQueries({ queryKey: queryKeys.projects.lists() })
queryClient.invalidateQueries({ queryKey: queryKeys.projects.detail(slug) })
```

### 6.2 Service 函数签名规范

```typescript
// features/projects/services/project.service.ts
import { supabase } from '@/services/supabase/client'
import type { Project, ProjectFilters, ProjectWithTags } from '../types'

export async function fetchProjects(filters: ProjectFilters): Promise<Project[]> {
  let query = supabase
    .from('projects')
    .select('*')
    .eq('status', 'published')

  if (filters.tag) {
    query = query.contains('tech_stack', [filters.tag])
  }

  if (filters.sortBy === 'newest') {
    query = query.order('created_at', { ascending: false })
  }

  const { data, error } = await query
  if (error) throw error
  return data as Project[]
}

export async function fetchProjectBySlug(slug: string): Promise<Project> {
  const { data, error } = await supabase
    .from('projects')
    .select('*')
    .eq('slug', slug)
    .single()

  if (error) throw error
  return data as Project
}

export async function createProject(input: CreateProjectInput): Promise<Project> {
  const { data, error } = await supabase
    .from('projects')
    .insert(input)
    .select()
    .single()

  if (error) throw error
  return data as Project
}
```

### 6.3 统一错误处理

```typescript
// services/api/error.handler.ts
export class ApiError extends Error {
  constructor(
    public message: string,
    public code?: string,
    public statusCode?: number,
  ) {
    super(message)
  }
}

export function handleSupabaseError(error: unknown): never {
  if (error instanceof Error) {
    throw new ApiError(error.message, 'UNKNOWN')
  }
  throw new ApiError('An unexpected error occurred', 'INTERNAL')
}
```

### 7.2 暗色模式实现

- 策略：`class` 策略（在 `<html>` 上切换 `.dark` 类）
- 持久化：localStorage 存储用户选择
- 系统跟随：`prefers-color-scheme` 媒体查询
- 初始化：在 `<head>` 中内联脚本，避免闪烁（FOUC）

```typescript
// composables/useTheme.ts
import { usePreferredDark, useStorage, useToggle } from '@vueuse/core'

type ThemeMode = 'light' | 'dark' | 'system'

const mode = useStorage<'theme-mode'>('theme-mode', 'system')
const preferredDark = usePreferredDark()

export const isDark = computed({
  get: () => mode.value === 'dark' || (mode.value === 'system' && preferredDark.value),
  set: (value: boolean) => {
    mode.value = value ? 'dark' : 'light'
  },
})

export function useTheme() {
  const toggleDark = useToggle(isDark)
  return { mode, isDark, toggleDark }
}
```

## 十二、安全设计

### 12.1 Supabase RLS（Row Level Security）

**原则：**
- 所有表默认启用 RLS
- 公开数据：已发布状态所有人可读，未发布仅 owner 可读
- 写操作：仅 authenticated 且为 admin 角色的用户可执行

**示例策略：**

```sql
-- projects 表：已发布公开可读
CREATE POLICY "Published projects are viewable by everyone"
  ON projects FOR SELECT
  USING (status = 'published');

-- projects 表：admin 可写入
CREATE POLICY "Admins can insert projects"
  ON projects FOR INSERT
  WITH CHECK (auth.role() = 'authenticated');

CREATE POLICY "Admins can update projects"
  ON projects FOR UPDATE
  USING (auth.role() = 'authenticated');
```

### 12.2 敏感信息管理

- 所有密钥 / URL 走环境变量，绝不硬编码
- Supabase Service Role Key 仅服务端使用，绝不暴露到前端
- 前端仅使用 anon key，配合 RLS 保证数据安全

### 12.3 前端安全

- Vue 自动 HTML 转义，防止 XSS
- Markdown 渲染使用 DOMPurify 消毒
- 图片上传验证 MIME 类型与大小
