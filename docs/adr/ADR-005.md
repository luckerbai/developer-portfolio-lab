# ADR-005: 首屏性能策略（静态首页 + 路由懒加载 + vendor 分包 + 零 CLS）

**状态：** Accepted  
**日期：** 2026-09-25  
**关联文档：** [05-Git任务拆分与里程碑.md](../05-Git任务拆分与里程碑.md)

## 背景

Lighthouse 首跑：Performance 92 但 **CLS 0.123**、LCP 2.3s。CLS 排查发现两个非预期根因：
1. 路由守卫对**所有**页面（含公开页）等待 Supabase Auth 初始化（`loading.value` 轮询 100ms+），阻塞首帧内容渲染
2. 首页组件懒加载导致两阶段渲染：先渲染 header+footer 空布局，chunk 到达后再填充内容 → footer 被推下 ~1800px → 大 CLS

## 决策

1. **路由守卫只对 Admin 路由等待 Auth**：公开页面首帧不再阻塞
2. **首页（HomeView）改为静态引入**：进入主 bundle，首帧一次渲染完整页面；其余路由保持动态 import
3. **骨架屏与真实内容同构**：Featured 区块骨架 count 与真实数据对齐，加载态高度 = 内容高度
4. **Vendor 分包**（Rollup `manualChunks` 函数形式）：`vendor-vue / vendor-query / vendor-supabase` 独立 chunk，并行下载 + 长缓存
5. **布局防塌陷**：`<main>` 设 `min-h-[70vh]`，路由切换期间 footer 不被顶上

## 后果

**正面**
- **CLS: 0.123 → 0**（满分）
- LCP: 2.3s → 2.0s；Interactive: 2.8s → 2.3s
- Lighthouse Performance **94** / Accessibility 94 / Best-Practices 100 / SEO 91
- 主 bundle 390KB → 拆成 index(42KB) + vue(97KB) + query(102KB) + supabase(215KB) 并行加载

**负面 / 权衡**
- 首页静态引入使其依赖进入主包（+~7KB gzip，换取首帧完整性，净收益为正）
- 骨架 count 与数据量耦合（注释已说明数据增长时需同步更新）
- vendor 分包牺牲了部分 HTTP 缓存命中率（换并行下载，实测收益为正）

**验证方式**：`scripts/cls-probe.cjs`（Playwright 注入 PerformanceObserver 实证位移为零）+ `scripts/lh-scores.py`（本地 Lighthouse 复测）。
