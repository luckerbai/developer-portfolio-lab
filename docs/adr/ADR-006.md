# ADR-006: 国际化方案（vue-i18n + 浏览器语言检测）

**状态：** Accepted  
**日期：** 2026-09-22  
**关联文档：** [01-PRD-产品需求文档.md](../01-PRD-产品需求文档.md)

## 背景

平台面向招聘者（可能来自不同语言环境），需要简体中文 / English 双语，且"全部页面必须国际化，不能遗漏"（用户明确强约束——曾 4 次指出遗漏并最终全量修复）。

候选：
1. 硬编码中文 + 后补英文
2. vue-i18n 集中字典 + 浏览器自动检测
3. 多语言路由（/zh /en 分离）

## 决策

采用 **vue-i18n（legacy: false，组合式 API）+ 浏览器语言自动检测**：

- 字典集中管理：`src/app/locales/zh-CN.ts` / `en-US.ts`，按页面/区块分命名空间（`home.*`、`projects.*`、`resume.*`、`lab.*`、`admin.*`、`common.*`）
- 初始语言 = `navigator.language` 匹配（zh → 中文，否则英文）；Header 提供切换按钮
- 切换后持久化到 `localStorage`，刷新保持
- **验收红线**：任何用户可见文本（含 placeholder、aria-label、按钮、空态、错误态）必须走 `t()`，禁止硬编码——E2E 用 `locale: 'zh-CN'` 断言中文文案兜底

## 后果

**正面**
- 全站 100% 双语覆盖（最后一次全量补齐 Lab 6 个子页 + About + Admin 全部视图）
- 字典集中，新增文案不改组件结构
- 招聘者体验：自动语言 + 手动切换

**负面 / 权衡**
- 两份字典需同步维护（命名空间约定 + 文案 review 缓解）
- 语言切换不重新请求数据（数据来自数据库，与 UI 文案分离，行为正确）
- 修复过 1 处模板绑定语法（`placeholder="{{ }}"` → `:placeholder`）——此类绑定 bug 通过 E2E 中文断言可发现

**不选方案 3 的原因**：多语言路由重复页面结构、SEO 复杂度高，对单作者展示站点过重。
